# 章节解析

[English](en/chapter-analysis.md) · [使用手册](使用手册.md) · [项目入口](../README.md)

## 用途与操作

章节解析对已保存的正式章节调用用户明确选择的真实模型，输出独立的分析报告。它不是正文生成、自动返修或候选采用：不会修改正文、章节历史、候选稿、设定或发布队列，也不会自动上传到平台。

1. 先保存需要分析的正文；未保存的编辑内容和未采用候选不属于正式章节输入。
2. 在章节书稿页进入“章节解析”，选择手动章号范围（包含首尾）或最近 N 章，并选择可用的真实模型。
3. 核对范围与模型后主动发起。该操作会向所选模型供应商发送章节内容，并可能产生费用；选择范围、打开面板或查看旧报告本身不应触发模型调用。
4. 查看运行状态；完成后阅读报告。报告独立持久化，可离开页面后再次打开，不必重新付费生成。后续编辑正文不会把旧报告变成新版本的分析，应核对报告的源章节修订信息。

模型结论仅供作者参考，不是事实证明、质量保证或自动修稿指令。请勿将不允许发送给所选供应商的正文用于解析。

## 范围、限制与状态

- 单次最多 100 章；手动范围按章号选择，最近 N 章针对已保存的章节，而不是正文未保存草稿。
- 完整提示词上限 150000 字符，报告上限 100000 字符；超过上限拒绝/失败，不静默截断后伪装完整结果。完整提示词包含分析指令等开销，不等于正文可全部用满该额度。
- 不提供演示结果，不在模型不可用时自动改用其他模型，也不自动重试模型调用。失败后先检查状态，不要盲目重复创建付费请求。
- 状态为 `running`、`done`、`error`、`interrupted`。错误或中断不应当作成功报告，也不能证明供应商没有处理或收费。
- 每作品最多保存 100 条解析记录；达到上限时，新请求返回 `409 ANALYSIS_HISTORY_FULL`。不会驱逐历史记录或遗忘历史 `requestId` 来腾出容量，已有请求的幂等语义保持不变。
- 模型完成但结果持久化失败时，保留已经持久化的 `running` 记录，不伪装成 `done`，也不会再次调用模型。须先修复存储，再重启使遗留运行记录标记为 `interrupted`；不承诺自动恢复未成功保存的报告。
- 报告保存源章节 ID、章号、标题、修订号与 hash，不额外保存源正文副本。报告文本仍可能引用正文，应按作品内容保护，不公开分享敏感报告。

## API 契约

共享类型见 [shared/chapter-analysis.ts](../shared/chapter-analysis.ts)。所有路径仍遵循现有项目访问权限、租户隔离及写请求 Origin/CSRF 校验；本功能不同于仅管理员可读的 Token 统计。

- `POST /api/projects/:projectId/chapter-analyses`：请求体为 `{requestId, selection, modelId}`，`requestId` 是 UUID，`modelId` 必须明确指定。
- 手动范围：`selection: {kind: "range", from: 1, to: 10}`；最近章节：`selection: {kind: "recent", count: 10}`。章号/数量使用有效正整数，实际选择不得超过 100 章。
- 新请求返回 `202` 及直接的 `running` 记录，不使用额外记录包装层。同一 `requestId`、相同请求参数幂等重放返回 `200` 及原记录，不另发一次模型请求；同 ID 不同参数返回 `409 ANALYSIS_REQUEST_CONFLICT`。有意重新分析应明确创建新请求，而不是把幂等重放当作重跑。
- `GET /api/projects/:projectId/chapter-analyses`：直接返回记录数组。
- `GET /api/projects/:projectId/chapter-analyses/:analysisId`：读取单份记录。读取报告不会再次调用模型。
