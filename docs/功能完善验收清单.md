# 功能完善与验收记录

本轮对应原审计 P1 / P2 / P3 与统一文件安全入口。本文区分本地实现与真实外部验收，未提供真实平台资质、模型或数据库凭据时不作外部成功声明。

## P1

| 项目 | 本轮实现 | 范围 |
| --- | --- | --- |
| 字数硬校验 | 按 Unicode 字母/数字计数，排除空白、标点和 emoji；最小/最大值阻止采用 | target 仍为写作建议 |
| 审校返修 | 自动模式结构化审校、明确否决阻止采用、有界重写并重审 | 语义判断是模型判断，不等于事实正确；手动保留作者决策 |
| 长篇上下文 | 从当前目标之前的实际正文检索相关片段，保留最近章节并按预算裁剪，加入全局/先前章节事实 | 本地文本检索，不冒充向量语义召回；不引入未来章节 |
| 草稿保护 | 按账号、项目、工作流、章节隔离的本地持久草稿和刷新恢复，存储失败保留内存稿 | 不提供跨设备同步；保存期间继续输入不会被旧响应覆盖 |
| 章节历史 | 历史查看、对照及 CAS 恢复，恢复生成新修订且保留恢复前正文；统一最近 20 版 | 不是无限历史备份 |
| 中断续跑 | 原工作流与目标快照验证后仅执行未完成目标，拒绝配置/原稿变化 | 不能恢复上游供应商已中断的网络流；不得重放已保存章节 |

## 文件准入安全

统一入口覆盖资料、封面、正文 TXT、DOCX 阅读；本地头像先检查后使用。图片完整解码、尺寸限制并重编码为无元数据 PNG；文本严格解码并拒绝二进制；DOCX 检查压缩包路径/膨胀/危险内容后在子进程转换为净化正文。未配备 PDF 内容重构能力时拒绝 PDF，不把简单签名检查当作安全放行。旧上传图片的下载和模型出站读取也必须再次净化，禁止绕回原始文件。

并发名额、取消时机、解码超时、输入输出边界和最小子进程环境均有测试。此实现是应用级隔离与内容重构，**没有 Windows AppContainer / Linux 无网 namespace 等操作系统级隔离**。V8 堆上限不等于原生解码库 RSS 上限，也没有“绝对安全”证明。部署到敌对文件来源环境前应增加操作系统资源和权限隔离。详见 [文件沙箱](文件沙箱.md)。

## 后续 UI 与安全加固

- 调度数字字段使用输入草稿，提交时检查整数 1–4；节点状态轮询不再覆盖未保存配置。
- 模型保存时锁定输入；扩展配对明确区分加载、空状态与处理中；知识输入提供可访问名称；历史恢复失败就地显示，比较区域适配窄屏及键盘滚动。
- 修复知识 PATCH 对新标签与章节关联未生效、返回旧修订的问题。关联检查发生在持久化前，非法关联不改变事实。
- HTTP 请求计数不保存无限增长的时间数组；每窗口最多 240 次、最多保留 4096 个客户端，过期清理且不通过淘汰活跃客户端重置额度。429 返回重试等待时间。此限制按进程生效，不是分布式防护。
- 继续审查认证、租户隔离、扩展能力和文件准入，未确认新的可复现越权漏洞；不把测试通过视为不存在所有漏洞。
- 更新解析与数据库相关依赖，固定兼容的 `tedious 19.2.2`、`@azure/identity 4.13.0` 与 `uuid 11.1.1`，重新解析锁文件并同步安装后，`npm audit --json --registry=https://registry.npmjs.org` 报告 0 个漏洞（含开发依赖）。此结果仅代表核验时 npm 公告库的匹配结果。

## 网关与身份切换增量验收

- 本机网关默认关闭，可显式配置 5173/5174/5175 等回环别名，全部转发到同一后端，不启动多份数据写入实例。入口和租户 Worker 均显式接收别名来源配置，未知端口、恶意 Origin 和别名局域网 Host 被拒绝，业务写入仍需 CSRF。
- 修复外层租户入口独立使用无限时间数组的限流缺口，改为有界计数器并返回 `Retry-After`；不信任客户端转发地址。网关启动在主服务监听成功后进行，异常启动与关闭有总退出时限。
- 工作流调度表单在首次渲染即从已保存条件/汇合规则初始化，减少空初始输入；浏览器验收等待异步项目刷新后断言持久值，完整创作验收 **10 / 10** 通过（第一次复跑暴露了刷新后过早断言，已修正初始化与等待后复验）。
- 同 host 的登录 Cookie 跨端口共享，但 localStorage 不共享。页面焦点/可见性恢复时向服务端重验身份，身份变化后清缓存并刷新；身份不变时不卸载脏草稿。离线失败不推断匿名或认证关闭，过期响应不安装旧身份。
- `npm test`：最新完整回归 **495 / 495** 通过；`npm run build` 通过（主 bundle 约 838 kB，仍有拆包警告）。网关/租户/身份专项 **22 / 22** 通过。
- `npm run smoke:auth`：一次性部署、独立随机测试密码、环境白名单，真实浏览器通过正常登录/退出验证管理员与作者双向项目读写隔离、作者章节持久化、旧会话与旧租户 CSRF 拒绝、身份缓存清理及语言保留，重启后会话和内容仍有效。同 host 双端口还验证 Cookie 共享、身份未变化时聚焦不刷新，切换作者后别名页面聚焦重新校验并清理管理员缓存。无测试身份后门，不改变真实数据认证。
