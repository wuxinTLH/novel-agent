# Novel Agent

语言 / Language：[中文](使用手册.md) · [English guide](en/user-guide.md) · [English documentation index](en/README.md)

面向本机和可信局域网的小说创作工作台，版本 `v0.0.2a`。支持多作品、多工作流、世界观编写、章节创作、资料管理、模型库、主题和数据保存；默认免登录单用户，可通过本地管理 CLI 显式启用认证与租户隔离，不是公网生产部署方案。

## 快速开始

需要 Node.js 22.16 及以上版本。

```powershell
npm ci
npm run browser:install
npm run dev
```

开发界面是 `http://127.0.0.1:5173`，API 是 `http://127.0.0.1:3001`。

生产运行：

```powershell
npm run build
npm start
```

生产界面是 `http://127.0.0.1:3001`。服务监听本机及局域网接口，仅供可信局域网使用，不要暴露到公网。

## 使用手册

### 页面

- `/workflow`：创作工作流，可新建、切换、整理和运行节点。
- 左侧“创建人物”“创建世界观”会建立对应的独立工作流；“创建小说”会新建作品或小说工作流。
- `/assets`：设定资料，保存世界观、人物、剧情和章节资料。
- `/chapters`：章节书稿，编辑、生成、对比和导出章节。
- `/platforms`：平台概览，点击番茄进入独立二级页面。左侧步骤导航、右侧当前操作；依次核验账号、绑定作品、选择章节、预览并批准、核对结果。前置条件不足时无法跳至写入步骤；核对结果即使会话过期仍可查看。番茄支持草稿新建/复用/覆盖和回读核验、批量送审、显式自动审批及完整工作流自动接续；送审不等于审核通过或已发布。
- `/settings`：模型库、协议、密钥、运行模式和可选 SQLconnect 数据库连接。

刷新页面会保留当前地址。未知地址显示 404，5 秒后返回上一页；应用错误可从错误页返回首页。

### 世界观编写

1. 点击左侧“创建世界观”。
2. 工作流包含开始、自写节点、扩写节点和结束节点。
3. 可填写世界观名称；留空时根据内容生成名称。
4. 运行后只保存世界观正文到设定库。
5. 设定审查、假设标注、章节规划和小说正文不会写入世界观。

世界观流程不创建章节。章节创作应使用独立的章节工作流。

### 人物编写

1. 点击左侧“创建人物”，建立独立人物工作流。
2. 工作流默认提供人物编写节点，可继续添加节点并调整连线。
3. 运行结果保存到设定库的“人物设定”分类；生成目标名称留空时按内容自动命名。

### 作品封面与本地头像

- 在工作流页点击“作品设置”，可编辑作品名称、类型和简介，并上传不超过 4 MiB 的 PNG、JPG 或 WebP 封面。
- 点击顶栏或侧栏头像可上传自定义头像。头像只存储在当前浏览器本地，不会上传到服务器。
- PowerShell 7 默认启用 Tab/Shift+Tab 菜单补全；支持虚拟终端时也会启用历史与插件预测列表。

### 章节创作

新建作品的默认章节图为「章节规划 → 正文生成 → 一致性审校」，每章三次模型调用（不含失败重试、自动返修或自定义节点）；审校仍为独立步骤。世界观、剧情编排可在独立设定工作流中准备，或按需添加到自定义章节图；已有作品的已保存图和提示词不自动改写。生成运行模式必须与工作流类型一致，正文图不能通过切换“世界观模式”来跳过正文节点。

冲突、反转、高潮与伏笔节点是按创作需要选择的可选预设，不会自动加入默认章节图，也不要求每章全部执行。建议按目标选择少量节点，连接到需要其结果的规划或正文节点；不要把推荐编排理解为必须付费运行的固定流程。

节点并发上限可配置为 1–8（缺省 1），只在同一章存在相互独立且安全的分支时并行；线性默认图仍逐节点运行，章节批次仍逐章提交，不会并行写入章节。提高上限可能同时触发多个付费模型调用，故应结合模型配额与预算谨慎调整；失败、取消时不会以未完成输出保存正式正文。

1. 在模型设置中选择真实模型，或明确使用演示模式。
2. 从工作流或章节页打开“配置目标与要求”。
3. 选择续写、指定单章或章节区间。
4. 保存作品要求或章节要求后运行。
5. 手动模式下，已有章节重生成先产生候选稿，采用后才替换原稿；全自动模式通过审校、文本校验及版本检查后可自动采用。

演示模式输出固定模板，不代表模型质量。真实模型调用前必须配置有效地址、模型 ID 和 API Key。

### 手动添加正文与 TXT 导入

1. 打开“章节书稿”，点击“添加正文（上传 / 手动编写）”。每次添加一章，不需要调用模型。
2. 确认章号，填写标题和正文；也可先选择编码，再上传一份 `.txt` 文件。默认 UTF-8，旧中文文本可选 GB18030 / GBK；不猜测编码，读取失败时选择正确编码后重新上传。
3. 文件最多 **2 MB（2,000,000 字节）**，单章正文最多 **200000 个字符**。标题必填、最多 120 个字符；章号为 1–1000000 的整数，正文不能全为空白。Word、PDF 等需先另存为 TXT。
4. 文件名会在标题为空时作为标题初值。导入只去除开头 BOM、统一换行，不自动剥离正文标题或拆分章节；请在保存前检查正文，超限时自行拆章。读取失败保留原输入。
5. 点击“保存为正式章节”。正文保存到当前作品及工作流，可在书稿编辑器继续修改，也会出现在平台页可选章节中；这一步**不会上传或送审**。

同章号已有正式章节时会报冲突，不会覆盖；请改用空闲章号或编辑原章。界面对相同保存内容保留同一请求 ID，后端幂等重试返回原章，不重复添加；同一请求 ID 携带不同内容会拒绝。保存出错保留输入，先查看书稿是否已经保存，勿以改章号方式盲目补建。

### 文稿格式导出与 DOCX / PDF 临时阅读

1. 打开章节书稿页“文稿格式与阅读”。原 Markdown 导出保留；点击“导出 DOCX”或“导出 EPUB”，下载按章号排列的服务器正式 canonical 章节，不含编辑器未保存文字、未采用候选或临时阅读文档。
2. 需要 PDF 时点击“准备 PDF 打印”，检查稿件专用预览，再点击“打印稿件 / 另存为 PDF”，在浏览器打印对话框选 PDF。不是服务端生成 PDF，不打印整页应用；本机须安装合适中文字体，并人工检查分页与字形。DOCX / EPUB 同样依赖阅读器字体，未保证所有 Word / EPUB 阅读器排版一致。
3. 临时阅读当前仅接受单份 ≤ 8 MiB 的 DOCX。旧 `.doc` 不支持，请先用 Word / LibreOffice 另存为 DOCX。Word 阅读保留清理后的文本结构，图片、链接、样式及活动内容不保留。**PDF 上传当前拒绝**：尚无可靠内容重构能力；旧界面标签即使提及 PDF 也不代表允许上传。PDF 打印导出不受影响，不提供 PDF 文本提取或 OCR。
4. 临时副本仅在服务端内存中保留 30 分钟，重启丢失；点击“关闭并删除临时文档”可提前删除。不会导入章节 / 资料或上传第三方，不提供阅读历史。每项目最多 10 份、进程最多 64 份 / 64 MiB，最多两份同时处理，超限请删除旧副本或稍后重试。
5. ZIP 验证限制为 512 项、实际总解压 32 MiB、单项压缩比 200:1、5 秒；DOCX 独立进程转换限制 10 秒、4 MiB 输出、128 MiB V8 heap（不是 OS 总内存上限）。不能以 PDF 头尾签名检查代替内容重构并放行原件。清理、限额和沙箱**不是杀毒或完整文件合规扫描**，仅打开可信来源文件并保持浏览器更新。详细边界见 [文档模块](../packages/server/src/features/documents/README.md)与[文件沙箱](文件沙箱.md)。

### 番茄接入：安装、登录与作品绑定

本功能通过 Playwright 操作番茄作者后台，不是番茄官方 API 或客户端。安装依赖后，首次使用需安装 Chromium：

```powershell
npm ci
npm run browser:install
npm run dev
```

`browser:install` 的实际脚本为 `playwright install chromium`，仓库已声明 `playwright` 依赖，不必另装全局包。生产环境安装浏览器后按上文构建、启动。运行后端的机器必须能显示隔离浏览器窗口并访问番茄；不会附着或读取你日常浏览器的登录资料。

1. 先在番茄官方作者后台建好作品与分卷；本应用不为真实番茄创建或修改作品，也不新建分卷。
2. 在本应用选择本地作品，进入“平台连接”概览，点击番茄卡片进入二级页面。左侧按“核验账号 → 绑定作品 → 选择章节 → 预览并批准 → 核对结果”操作，右侧每次只展示当前步骤；不能跳过登录、绑定或预览直接上传。“核对结果”在凭据失效时仍可进入，用于查看历史与未知结果。在“核验账号”打开人工登录窗口，由作者本人完成扫码、密码、验证码等步骤；无需向应用粘贴 Cookie、session 或 token。
3. 回到应用点击“我已登录，核验作者身份”。隔离浏览器会进入作者后台并读取稳定作者身份；仅打开登录窗口不代表登录成功。确认显示的作者名称和稳定账号 ID 正确。
4. 在“当前项目连接”可点击“只读核验账号”。“本机有会话”不保证远端仍有效：远端操作前会重新核验当前作者，不以缓存昵称或旧登录标记替代身份检查。会话过期或身份不符时停止，在原连接下以原账号“重新人工登录”；要改用其他账号，应新建连接并显式重新绑定作品。新登录替换旧浏览器上下文。
5. 在“明确选择账号与作品”中显式选择账号，点击“只读读取作品”，核对作品名与远端作品 ID，再点“绑定此作品”。登录、选择账号、绑定本身均不上传章节。可用“只读刷新资料”更新绑定信息；解绑只解除本机关系，不删除远端作品或草稿。
6. 在“远端上传 / 草稿送审队列”选择目标绑定作品后，只读获取已有分卷。唯一卷自动选中；多卷时明确选择目标卷，不猜测。新建章节须选卷；已有章节可按已知 ID 定位，但要核对预览的卷名和卷 ID。需要显式选卷或覆盖时，建议统一使用此队列，即使只上传一章。

### 手动上传、草稿复用/覆盖与提交审核

1. 先保存本地正式章节。队列只使用服务器已保存版本，不含编辑器未保存内容和未采用候选稿。
2. 选择准确的绑定作品、目标卷、操作“保存草稿”或“提交审核”，勾选章节。每批 1–50 章，按章号顺序串行处理。
3. 送审须由作者据实明确选择“是否使用AI”，不设默认值：`useAi=1` 表示“是”，`useAi=2` 表示“否”。此声明随快照及批准哈希保存；自动审批和自动工作流也不能省略，应用仅按该明确选择操作平台对应选项，不自行判断或默认否认 AI 使用。
4. 保持“自动审批”关闭，点击“准备全部章节完整预览（不写入远端）”。逐章核对完整标题、正文、已保存版本、账号、作品、卷 ID、远端章节 ID、操作类型和覆盖前指纹。准备阶段会只读检查远端，但不会填入编辑器或保存正文。
5. 预览标注三种计划：**新建**（目标卷无同章）、**复用**（已有可编辑草稿与本地一致）、**覆盖**（同一草稿 ID 的正文/标题不同）。覆盖保留远端 ID；执行前再次检查远端指纹，若期间被修改则拒绝覆盖。远端同章有歧义、已知 ID 消失、已发布或审核中时，不会强行覆盖或改建重复稿。
6. 勾选“我已逐章核对……”后点击“人工批准并启动此批次”。账号、绑定作品、正文版本、目标卷或远端草稿变化会阻止原批准继续生效，须核对后重新准备。
7. 查看逐章状态和远端 ID。“草稿已回读核实”仅代表重新打开后核对成功；“已提交审核”表示取得匹配作品、章节 ID、标题及即时送审状态的回执，**不代表审核通过或已发布**。平台上的“确认发布”按钮在本流程中是送审入口，不是绕过审核。

番茄分离章号/标题编辑器支持 `第1章 标题` 和 `第 1 章 标题`，数字须与本地章号一致；只适配章号格式，不改写正文或标题后缀。若使用上方“单章草稿”入口，先选择账号、作品和已保存章节，准备完整预览、勾选批准再执行；需要明确卷或修改历史草稿时使用上述队列，不绕过单章入口的版本冲突保护。

验证码、风控、额外声明、风险提示或未知确认界面均需作者人工处理，应用不会自动同意原创性或其他额外授权，也不会绕过平台审核。本功能不提供无人值守定时发布；网站改版可能导致适配停止，真实账号端到端流程仍需作者现场核验。

### 自动审批与自动化工作流

这是两个独立设置，不要把本地“审批”理解成番茄审核：

- **自动审批复选框**：在平台页“远端上传 / 草稿送审队列”打开“自动审批：后续操作跳过本地人工批准，准备后直接上传 / 送审”。默认关闭，按本地作品 ID 保存在当前浏览器 localStorage（`publication-auto-approve:<projectId>`）；刷新同一浏览器会保留，不是跨浏览器或服务器全局配置。开启后点击准备即自动批准并启动，不再等待第二次人工确认；也影响单章草稿入口。仍执行账号、绑定、分卷、完整正文、版本和重复操作检查，送审仍须明确选择 AI 声明。关闭可恢复逐批预览批准。
- **工作流远端接续**：按当前工作流持久保存到项目数据，与上述浏览器复选框互不替代。仅选择全自动生成，不等于已经允许上传；仅打开自动审批，也不等于工作流完成后会上传。

配置完整工作流的自动接续：

1. 在当前工作流设置中将运行方式选择为“全自动 · 启动后无需逐章确认”（`automationMode='automatic'`），配置目标章节范围、模型和创作要求。通过审校及硬性文本校验后，自动保存正式章节；重生成版本满足检查时自动采用，冲突会停止。
2. 到平台页队列选择准确绑定作品、目标卷和操作；送审时明确选择 AI 声明。点击“保存当前选择并启用全自动接续”（或“使用上方目标启用 / 更新全自动工作流”）。此操作也将当前工作流设为全自动，并保存显式 `publication` 配置：`enabled`、`linkId`、`volumeId`、`action` 和送审时的 `useAi`。核对界面显示已配置的绑定、卷及动作。
3. 回到工作流，以真实模型运行**完整工作流**。只有 `live` 模式、完整运行成功结束（`done`）、本次生成章节全部完成且校验通过，并且正式章节确属本次运行时，才自动按章号准备、批准和启动远端队列，无需再勾本地人工批准。
4. 到平台队列查看上传/送审结果。只接续本次运行产生并保存的正式章节，不把既有全部书稿或候选稿一并发送。演示运行、单节点运行、失败/取消/未完成运行、校验失败或没有正式章节的运行不上传。手动添加正文也不会触发工作流接续，需在平台页手动选章。
5. 不再需要时点击“关闭工作流远端接续”。关闭接续不会撤回已经发往番茄的操作。切换工作流后核对该工作流自己的配置，不能凭另一个工作流的设置推断已启用。

### 暂停、未知结果与重启恢复

- 运行中可点“当前一章后暂停”：当前章结束后不再开始下一章，不撤销已开始的写入。剩余章节须人工点击恢复；自动审批开启时可省去本地批准勾选，但不会自动恢复。
- 请求中断、超时或失败后先点“刷新本地队列状态（只读）”，查看每章记录，不盲点重发、不新建批次补发。结果未知会阻止继续发送。
- 对未知批次进入“核对结果”点击“只读核对远端结果（不重发）”。优先使用已持久记录或覆盖/复用计划中的精确远端章节 ID；缺失时可从番茄官方后台**该章编辑链接**人工复制准确章节 ID（不是作品 ID）作为候选。随后只读检查作者、作品、卷、历史快照的完整标题与正文；送审还须核对送审回执。不会按同名标题猜测 ID、重新填正文或再次点击送审。
- 候选 ID 不存在、证据不足或内容不一致时保持未知，需到番茄官方后台人工核对，不把“没找到”解释为可以重发。核对成功后，全章已完成的批次变为完成；还有剩余章则暂停等待人工恢复，不自动续跑。
- 服务重启不会自动重放上传、自动接续或恢复队列。被中断的写入可能成为未知，尚未开始的部分暂停；即使浏览器复选框和工作流配置仍在，也须先核对本地与远端结果，再显式处理。自动接续失败或中断不会自行重试。

### 本地暂存、隐藏历史与高级清空

- “移出本地暂存列表”只在当前浏览器隐藏非活动批次或草稿操作，不删除本地章节、远端草稿、服务端审计记录或未知结果防重复限制。可在“核对结果”点击“恢复显示全部批次 / 历史”找回显示；换浏览器也不会清除服务端记录。
- “备份并清空本地暂存（解除历史阻塞）”与隐藏记录不同：确认重复风险后，备份并清空当前作品的本地平台预览、操作、回执及**全部批次（包括已隐藏记录）**，会解除相应历史去重阻塞，之后上传可能生成重复章节。它不会删除本地正式章节、登录绑定或番茄远端正文，也不会自动重新上传。仅在核对官方后台并确实需要恢复时使用，保管好本机备份。

### 登录会话保持

身份核验、只读读取及成功上传/送审后，应用同步隔离浏览器实际更新的 Cookie / localStorage，保存浏览器真实会话状态；没有臆造的“双 token”刷新协议，也不会调用猜测的刷新接口。

跨后端重启保存会话，须在启动服务前配置固定且足够保密的 `PLATFORM_SECRETS_KEY`（可放在未提交的 `.env` 中），并在以后每次启动沿用同一值；不要每次生成新密钥。凭据按该密钥加密保存在本机平台凭据文件中，不返回前端。未配置时会话只保存在进程内存，重启后绑定仍在，但须在原连接下重新人工登录。密钥丢失或更换会导致旧凭据无法解密，应先保护原数据，不手改凭据文件或把密钥粘到报错/截图中。

持久化不保证网站永久登录：番茄主动撤销/过期会话、验证码或风险控制均需重新人工登录；应用不绕过这些要求。

### 模型库

- 可添加多个模型，并在列表中切换当前模型。
- 支持 Chat Completions、Responses API 和 Anthropic Messages。
- 当前模型与运行模式默认保存在租户数据目录的 `models.json`，显式迁移后保存到所选 SQL profile；模型密钥仍在本地，重启后继续使用。
- API Key 加密保存，不返回浏览器，也不写入项目内容。
- 只有模型库为空时才创建初始“默认模型”。已有模型不会在每次启动时被替换成演示模式。

### 节点配置与人物生成

1. 在工作流画布选中节点，打开“节点配置”，核对提示词、关联设定和直接上游结果。关联设定留空表示使用全部设定。
2. 节点模型可选“跟随全局模型”或单独指定可用模型。指定模型被删除、禁用或未配置密钥时，先修复配置再运行，不会静默回退。
3. 人物节点可设置姓名、性别、性格、经历和人物模板，数量为 1–100 的整数；留空字段允许按资料生成。编辑字段后移开焦点保存，并确认提示成功。
4. 新建节点使用共享提示词预设；已有节点提示词不自动替换。开始节点为系统边界，不调用模型。

### SQLconnect 数据库连接（可选）

默认作品、章节和资料仍使用本地 JSON。原 SQLconnect 设置负责连接测试和预留表初始化，不自动迁移、不切换存储，也不启用用户认证。新的 v3 多 profile 关系存储另用离线 `maintenance migrate-all` 显式迁移；MySQL / PostgreSQL / SQL Server 均有适配器，但 **MySQL / SQL Server 当前仅模拟验证，真实数据库尚待验收**，连接探测成功不等于完整业务验收。旧 PostgreSQL v2 迁移仍保留为 legacy。

1. 先在数据库服务中创建目标数据库和具备所需权限的账号；初始化不会创建数据库。
2. 在设置页找到“SQLconnect · 数据库连接”，选择 MySQL、PostgreSQL 或 SQL Server，填写服务器、端口、数据库、用户、密码和超时（1000–30000 毫秒）。
3. 默认启用 TLS 并验证证书；仅 localhost 或回环地址允许关闭 TLS。修改字段后先点“保存数据库配置”，保存本身不连接或建表。
4. 已保存密码时，密码输入框留空保留原密码；明确勾选“清除已保存的数据库密码”才会清除。
5. 点击“测试连接”，只执行固定连接探测，不创建表。确需准备数据库结构时，先备份，再点击“初始化数据库”并确认目标数据库。
6. 旧初始化可能因权限、超时或重启留下部分结构；修复原因后经确认重试，不将它当作业务迁移或修复工具。未激活 SQL 业务后端时，配置损坏只停用 SQLconnect；已激活后配置或连接出错会阻止业务存储使用，必须停服修复，不会回退到旧 JSON。

**数据库密码以明文存于数据目录的 `sqlconnect.json`，不是加密模型密钥。** 必须保护目录、Windows ACL、系统账号和备份。部署除构建输出外，还须保留构建输出中的 `build/packages/server/src/infrastructure/storage/sql/` 初始化脚本及 `migrate_postgresql_v2.sql`（`npm run build` 自动复制）。原有连接配置细节见 [SQLconnect 说明](sqlconnect.md)；当前存储与租户运行边界见 [服务说明](services.md)。

### 认证与本地管理 CLI

所有管理命令均由 `packages/server/src/features/administration/admin.ts` 实现；**先停止服务，完整备份，再执行，成功后重启**。CLI 同样获取数据目录锁，不能与服务同时运行；默认目录为应用根目录下的 `data`，自定义目录须显式追加 `--data-dir <PATH>`，不要假定 CLI 会沿用服务的 `DATA_DIR` 环境变量或自动加载 `.env`。每条修改命令必须带 `--confirm`。可用 `npm run admin -- --help` 查看参数。

1. 通过安全方式预先注入 `NOVEL_BOOTSTRAP_PASSWORD` 环境变量（至少 12 个字符、最多 1024 字节），不要在命令行参数、文档、日志、截图或 Git 中写密码。执行：

   ```powershell
   npm run admin -- bootstrap-admin --username admin --confirm
   ```

   首次超级管理员只能本地 CLI 引导，没有 HTTP 管理员引导入口；可选公开注册仅创建邮箱确认的普通用户，默认关闭。记录输出的 `ownerId` UUID；完成后从当前终端环境移除引导密码。

2. 明确选择旧数据归属。如果需要 SQL，建议先在认证仍关闭时完成下节 v3 全量迁移，再显式启用认证；纯本地 JSON 可直接继续。将以下 `<UUID>` 替换为已有且未禁用用户的真实 UUID，不是用户名：

   ```powershell
   npm run admin -- enable-auth --owner <UUID> --confirm
   ```

   此命令同时指定旧目录 owner 并启用认证。仅没有旧业务文档 / 上传 / 密钥 / 浏览器等旧资产、没有 SQL 激活清单的新目录才可改用 `npm run admin -- enable-auth --no-legacy --confirm`。首次登录者不会自动获得旧作品或凭据。

3. 如需独立显式分配旧目录，可在停服时执行 `npm run admin -- assign-legacy --owner <UUID> --confirm`；它保持当前认证开关，不是跨租户复制命令，已有不同归属或 SQL owner 冲突会拒绝，不要手改清单绕过。
4. 显式开启认证后重启使用登录页。超级管理员可创建 / 启停用户、修改角色、重置密码、撤销会话及配置 Turnstile；不能停用或降级最后一个有效超级管理员。普通用户只能在账号安全中改自己的密码及查看 / 撤销自己的会话，不能管理其他账号、Turnstile 或 SQLconnect。改密 / 重置密码撤销该用户全部旧会话，角色变更及停用也撤销会话。认证模式下管理员重置密码需要重新验证自己的当前密码。超级管理员身份不授予读取其他租户业务内容的权限。
5. 若确需关闭认证，停服后执行 `npm run admin -- disable-auth --allow-public-access --confirm` 并重启。`--allow-public-access` 仅表示确认免登录暴露风险，不是允许公网生产部署；关闭后原默认 owner 的数据重新可免登录访问，应先核对可信局域网边界。

每个验证后的稳定用户 UUID 对应独立且不切换 owner 的 Store、Runner、模型密钥、平台运行时、发布队列及上传路由。legacy owner 沿用原目录，其余用户位于 `DATA_DIR/users/<SHA-256(user UUID)>`，SQL 文档按 owner 隔离；不信任客户端自报用户 ID。未登录不会回落共享数据。停用账号会撤销其会话；退出不会自动取消已开始的后台任务。

Cloudflare Turnstile 默认关闭。管理员须填写真实 site key / secret、action 和 hostname，启用后登录由服务端向 Cloudflare siteverify 核对 success、action、hostname，失败或无法联网时拒绝登录。secret 加密保存，不返回浏览器；公开 site key 不是秘密。必须另行用真实密钥和域名验收，目前未宣称真实 Cloudflare 在线验证已通过。

### 可选注册、邮箱恢复、OIDC 与双重验证

这些能力和认证总开关默认全部关闭，修改配置不自动启用认证。先按上节完成超级管理员引导、归属及认证开启，再选择所需能力；不需要的能力保持关闭。

- **邮件前置**：仅 `NOVEL_SMTP_ENABLED=true` 才启用可选 nodemailer SMTP。安全注入 `NOVEL_SMTP_HOST`、`NOVEL_SMTP_USER`、`NOVEL_SMTP_PASSWORD`、`NOVEL_SMTP_FROM`；可选 `NOVEL_SMTP_PORT` 默认 587，`NOVEL_SMTP_SECURE=true` 时默认 465。显式启用却配置缺失会启动失败，证书验证保持启用。不要把真实密码写进命令参数 / 文档 / Git。服务端未提供邮件传输时不能开启注册、验证或恢复。
- **配置与入口**：进入管理中心“系统与安全 → 账户功能配置”（AccountAdminSettings）。基础账户能力将 registration、emailVerification、passwordRecovery、mfa 分组为带说明的开关卡片，并显示已启用数量；下方填写邮件回链使用的 HTTPS `publicOrigin`。宽屏开关和 OIDC 字段使用双列响应式网格，窄屏改为单列。编辑后核对“有未保存的更改”，点击“保存配置”才提交；保存中控件禁用，密钥留空保留原值，服务端不返回明文。配置不会自动打开认证总开关。登录页按能力显示注册、找回密码和 OIDC，登录后“邮箱与双重验证”管理邮箱 / MFA，“账号安全”保留密码 / 会话管理。可用 `GET/PUT /api/admin/account/config` 核对完整配置；具体键见 [认证模块说明](../packages/server/src/features/auth/README.md)。
- **注册与邮件**：公开注册只能创建普通用户，必须经邮件确认，不自动登录；单次令牌 15 分钟到期，链接使用 `/account/complete#purpose=...&token=...`，不要截图或分享。找回响应不透露邮箱是否存在；完成重置撤销旧会话、保留 MFA。自己的邮箱变更须已登录并完成验证，邮件发送失败 / 超时不要推断已完成。
- **OIDC**：在同一配置卡片单独启用 OIDC，展开“连接与密钥设置”，填写 issuer、clientId、authorizationEndpoint、tokenEndpoint、jwksUri、redirectUri；可选 clientSecret 留空时保留已存值。全部启用地址要求 HTTPS。回调使用 `/api/auth/account/oidc/callback`，提供商须支持 code + PKCE S256，使用 JWKS 签名、issuer / audience / nonce / state 验证，不是普通 OAuth。先通过 `PUT /api/admin/account/oidc/users/:id` 把精确 issuer + subject 关联已有用户；不按邮箱自动合并或注册，不把邮箱冒充稳定身份。
- **MFA**：在“邮箱与双重验证”生成 TOTP 设置，用认证器当前验证码确认后启用；10 个恢复码只展示一次，须线下安全保存，不存项目正文 / 浏览器持久存储。启用、移除因素撤销旧会话。登录先验证密码 / OIDC，再以新鲜 TOTP 或单次恢复码完成第二步，之前没有业务会话；同一 TOTP counter / 恢复码不能重放。移除需有效因素，密码恢复不绕过 MFA，仍有已绑定因素时不能关全局 MFA 开关绕过。

**HTTPS 部署前置**：服务仍使用 HTTP；邮件回链 / OIDC 必须由自行配置的可信 TLS 反向代理提供 HTTPS。启动前设置 `NOVEL_TRUSTED_PUBLIC_ORIGIN=https://novel.example.com`（示例须替换），只允许一个 HTTPS origin，无账号密码、非根路径、查询、片段、通配符。代理保留浏览器 Host（含非默认端口），清除不可信转发头，并用防火墙阻止外部绕过代理直连后端；服务不信任 `X-Forwarded-*`，不会因该变量自动安装证书或提供 TLS。启用该变量即为认证 Cookie 设置 Secure，因此必须使用 HTTPS 入口，不要再用 HTTP 登录。账号配置 `publicOrigin` 使用同一 origin，OIDC `redirectUri` 为该 origin 下的回调路径；HTTPS Origin / Host 精确匹配，不扩大免登录本机管理员权限，也不开启认证。变量非法会启动失败，勿以关闭验证解决。

配置账户扩展后不要直接降级旧程序，旧 schema 可能丢弃扩展字段。SMTP、真实 OIDC、中文邮件和 HTTPS / 安全 Cookie / 反向代理仍须独立在线验收；默认部署仍限本机 / 可信局域网，不应因新增账号功能直接开放公网。

### 管理界面与默认关闭认证

认证与 Turnstile 仍默认关闭，首次超级管理员只能通过上述停服 CLI 引导；数据库配置、迁移和创建用户不会自动开启认证。管理中心默认进入“工作台”，汇总认证状态、账号数量、数据存储与租户运行时，并提供“用户、数据库、备份与维护、系统与安全”四个快捷入口。桌面使用侧栏，窄屏使用可横向滚动的分类导航；维护区采用三步引导，高级离线命令默认折叠。实际恢复、迁移仍无在线执行接口，必须停服 CLI。

认证关闭时，仅真实 socket 回环地址 + 本机 Host + 存在时本机 Origin 能获得管理权限，跨站请求拒绝；写入还需 `X-Admin-CSRF`，不信任代理转发头。局域网用户可以免登录使用业务，不代表可以管理。开启认证后管理按[显式角色权限矩阵](roles-permissions.md)授权，写入另需有效会话及 CSRF。普通用户账号安全提供修改密码、当前会话列表及撤销；列表不返回原始 token。

接口摘要：`POST /api/auth/password`、`GET/DELETE /api/auth/sessions`、`DELETE /api/auth/sessions/:sessionId`；管理员 `PATCH /api/admin/users/:id` 管角色 / 启停，`POST /api/admin/users/:id/password` 重置密码，`GET/DELETE /api/admin/users/:id/sessions` 和 `DELETE /api/admin/users/:id/sessions/:sessionId` 管会话。用户列表 / 创建继续使用 `GET/POST /api/admin/users`。

### 全量迁移到 v3 关系存储

1. 保持默认认证开关不变，先完成身份 / legacy owner 归属规划。在数据目录准备 `storage-profiles.json`，包含默认 profile、数据库连接及 owner 映射，详见 [配置样例](sqlconnect.md#v3-storage-profiles)。自行创建目标数据库、配置最小所需建表 / 读写权限，明文密码不得入 Git。
2. 停止所有共享目标数据库的应用实例 / 租户运行时，本机数据锁无法阻止另一主机。选择数据目录外、尚不存在的备份目录，使用明确 owner UUID：

   ```powershell
   npm run maintenance -- migrate-all --owner <UUID> --destination <EXTERNAL_BACKUP> --confirm
   ```

   自定义数据目录追加 `--data-dir <PATH>`。维护 CLI 加载应用根目录的 `.env`；数据目录仍默认是应用根目录的 `data`，不要假定 `DATA_DIR` 替代 `--data-dir`；外部秘密须安全注入。

3. 命令先创建完整应用备份，再校验全部租户映射、将源文档导入空 v3 目标、验证回读后写激活清单。非空目标、归属或路径不符会拒绝。它是离线显式操作，不是自动切换；不要手改激活清单绕过校验。该入口拒绝已有 SQL 激活清单，不支持直接把 legacy SQL 在线或原地升级为 v3；已有 legacy SQL 须独立备份数据库，另行规划迁移，不能简单删除清单。
4. 重启核对全部租户业务。v3 项目 / 章节 / 设定 / 工作流采用 canonical 实体表，保留文档结构、revision、导入 receipts；凭据、上传和浏览器目录仍本地。SQL 故障失败关闭，不自动使用旧 JSON。

持久连接池在数据库 Worker 中复用；租户 Worker 同步等待实际 COMMIT，同租户仍有等待屏障，其他租户和主控制面业务事件循环隔离，最多 32 个租户运行时。普通 SQL 操作按 owner 入场排队，不同 owner 可并发；完整快照、导入和迁移使用独占屏障。仍有数据库共享锁和性能瓶颈，MySQL / SQL Server 仅模拟验证，真实服务器未验收。认证控制面的同步 SQL 持久化仍可能有界阻塞主线程。单实例控制面现按服务端核验平台账号跨租户互斥；身份未知的登录占用整个平台锁，锁不可用失败关闭。不跨主机 / 多实例，也不防止官网 / 其他应用并发。

本地 SIMULATED [存储基准报告](../scripts/benchmark-storage-report.md) 使用四连接许可和 80 次模拟操作，八 owner 三轮约 254–261 ops/s，对照 profile 队列约 64–66 ops/s，单 owner 基本不变。无真实 SQL、网络、落盘，不是生产数据库性能证明。可选 [真实 v3 验收脚本](../scripts/test-relational-storage-live.ts) 须安全注入 `PGHOST` / `PGPORT` / `PGUSER` / `PGPASSWORD` / `PGDATABASE` 和 `STORAGE_LIVE_ALLOW_CREATE_DATABASE=1`，创建并清理本次两个唯一临时库，需要 CREATEDB 权限；尚未执行真实在线验收，不要把 v2 结果当成 v3 验收。

### 在线维护任务：备份、校验与恢复计划

1. 进入管理控制台“备份与维护”，按三步引导操作：**创建全应用备份 → 选择备份并校验 → 生成离线恢复计划**。创建前确认影响**全部租户、控制面及全部配置业务数据库**，勾选敏感材料与短暂停顿确认。本机模式不必先初始化账号即可使用受保护的管理入口；仅需要用户管理时再按高级命令完成引导。
2. 服务先阻止新请求 / 新租户，等待已接纳的控制面及后台操作排空并关闭所有租户 Worker / 浏览器，持有静默屏障和实例锁后导出快照；不能可靠排空时失败，不复制仍活动的数据树。完成后恢复接入。其他用户短时不可操作，请提前通知。
3. 查看阶段、状态及备份 ID。默认最多排队 8 项、保留 100 条终态记录、最多 20 个备份 / 未完成产物，满后由主机管理员安全整理。进度是阶段估计，不是字节百分比，也不是可靠完成时间预测；取消须等安全检查点，提交阶段不能取消。重启中断显示 interrupted，不自动重试；请求超时先核对列表，勿重复创建。
4. 产物存数据目录外的受管兄弟目录（默认 `data` 对应 `.data-managed-backups`），没有浏览器下载或任意路径访问。备份含密码 / 密钥 / 浏览器会话，应保护 Windows ACL、容量和独立外部密钥；不要把备份发到聊天或 Git。
5. 默认从最近成功备份下拉列表选择，无需手填 UUID；也可在任务记录中“选用此备份”。如果备份已不在最近历史，展开“使用已有受管备份 ID”输入其 UUID（不接受路径，实际存在性与安全性由服务端判断）。执行“校验完整性”或“离线恢复计划”。它们仅核对备份结构 / 哈希，不能证明密钥可解密、业务语义正确、目标数据库兼容；不会连接备份内源数据库、导入目标或执行恢复。**恢复 / 迁移仍必须停止所有相关运行时，再用下节 CLI**。没有定时备份 / 跨实例静默 / 跨库原子回滚保证。

### 全量应用备份与恢复

先停服所有共享数据库的运行时；备份目的目录必须在数据目录外且不存在。每次修改明确 `--confirm`：

```powershell
npm run maintenance -- backup --destination <PATH> --confirm
# 纯本地备份：无需目标数据库配置
npm run maintenance -- restore --source <PATH> --data-dir <NEW> --confirm
# 含 SQL 的备份：必须显式提供可信目标 profiles 文件
npm run maintenance -- restore --source <PATH> --database-config <EXPLICIT_TARGET_PROFILES> --data-dir <NEW> --confirm
```

- 完整应用备份包括安全数据树全部租户文件、上传、模型 / 平台秘密及本地密钥、浏览器资料、二进制和空目录；SQL v3 导出所有配置 profile 的应用仓库全部 owners / documents / 重建实体内容 / revisions / receipts，不局限当前用户或激活清单 owner。**不是整个数据库 dump**，不含其他表、数据库用户 / 权限、服务配置。
- 各层排除 `.instance.lock`、`.instance.lock.recovery`、`admin-backups`、`.maintenance-journal.json`、`*.tmp`、`.maintenance-*`；符号链接、硬链接和不安全路径拒绝。备份含明文 SQL 密码及会话 / 浏览器材料，须保护目录 ACL，不发到聊天 / Git。
- 仅在外部环境中的 `MODEL_SECRETS_KEY`、`PLATFORM_SECRETS_KEY` 不会进入备份，必须另行安全保存，并在恢复时注入；丢失则无法保证解密原秘密。
- **旧 version 1 的 SQL 激活后端不支持 maintenance backup**，须停服独立 `pg_dump` 加完整本地目录及外部密钥备份。旧 `admin-backups` 仍只是局部安全副本，不能代替完整备份。
- restore 默认只接受新 / 空本地目录、空 v3 应用数据库，拒绝覆盖。纯本地恢复不要求 `--database-config`；SQL 恢复必须用显式目标文件，不连接备份里的源数据库地址。目标 profile ID / owner 映射须能覆盖备份。
- 文件切换保留旧目录 rollback 副本，但不能自动原子回滚已提交的多个数据库。失败留下 `.maintenance-journal.json` 会阻止启动；先依据日志、完整备份和各目标持久状态人工安全协调，不要仅删除日志重试，不要假定数据库自动撤销。
- 恢复撤销认证会话，用户须重新登录；它不重放远端发布，平台已有结果须人工核实。单实例限制仍有效。

### Legacy：显式迁移到 PostgreSQL v2

以下仅为保留的旧 `admin migrate-sql` 流程，不是新 v3 多租户维护入口。

1. 停服前通过现有 SQLconnect 设置保存 PostgreSQL 配置至数据目录的 `sqlconnect.json`，先自行创建数据库；连接探测 / 初始化按钮不是迁移开关。SQL 业务激活后，界面禁止修改 / 清除连接配置或再次初始化；之后连接维护须由本地管理员停服处理。
2. 停服并独立备份完整数据目录及数据库。必须先按上节创建超级管理员，使用其返回 UUID 作为明确 owner；引导本身不会启用认证。导入 owner 必须是已有且未禁用的认证身份，不可随意生成 UUID。建议先迁移、后启用认证；首次迁移拒绝已有额外本地租户目录的布局，不会自动汇总其他用户数据。仅有账号身份但未产生租户目录不等于已迁移其数据。若曾以 `enable-auth --no-legacy` 启用认证，必须先停服执行 `assign-legacy --owner <UUID> --confirm` 明确归属，否则迁移会在数据库写入前拒绝，避免生成无法启动的配置；这不会绕过额外租户目录的迁移限制。
3. 使用的数据库账号须有 `public` schema 的 `USAGE` 和 `CREATE` 权限，仅能连接数据库并不足以初始化表。若返回 PostgreSQL `42501`，请由数据库管理员连接目标数据库后按最小权限授权；不要授予超级用户，也不要把容器内部端口误作宿主机映射端口：

   ```sql
   GRANT USAGE, CREATE ON SCHEMA public TO novel_test;
   ```

   上例仅用于测试账号 `novel_test`；实际部署替换为受控账号，并确认当前连接的数据库正确。然后执行：

   ```powershell
   npm run admin -- migrate-sql --owner <UUID> --confirm
   ```

   CLI 执行 PostgreSQL v1 初始化与 v2 迁移，在空 owner 文档目标中导入、回读核对，最后写入本地 `business-storage.json` 激活清单。归属冲突、非空目标冲突、来源改变或验证失败会拒绝；不要手工删清单或改 owner 后盲目重试。

4. 重启并核对作品、模型设置、平台连接和队列。旧 JSON 保留但不再是权威数据源，激活后不从旧文件重导入，SQL 故障也不自动回退。失败或结果未知时停下，核对备份和数据库持久状态；没有通用一键还原或 SQL 降级命令，不可将恢复旧文件当作完整回滚。

仅 `projects.json`、`models.json`、`platform-connections.json`、`publication-queue.json` 四类完整 JSON 文档快照进入 PostgreSQL 业务存储（认证状态另存全局文档），不是规范化业务表迁移。上传、模型密钥 / 加密密钥、平台凭据和浏览器配置仍留在各租户本地目录。

运行时同步子进程桥接会等到实际 PostgreSQL `COMMIT` 才返回，不是延迟写入，但会阻塞事件循环且每次操作新开连接。仅支持单服务进程与数据目录锁；SQL 行锁和 revision 校验不提供跨主机运行时安全，不要多实例共享 owner 运行生成 / 发布。未知提交结果会使当前存储停止，须重启核对，不能据此重发远端章节。

CLI 的 `admin-backups` 仅覆盖选定根目录文件，SQL 激活后追加清单 owner 的四类业务文档与全局认证快照；不含全部租户目录、上传、模型秘密或浏览器配置，也不是全库备份。必须另行停服备份完整目录、独立密钥与数据库，并保护备份中的明文 SQL 密码及认证材料。

### 界面

- 删除、放弃等操作使用应用内确认框，不使用浏览器原生 alert。

## 数据与安全

复制 `.env.example` 为 `.env` 后按需修改：

```dotenv
PORT=3001
MODEL_BASE_URL=https://api.openai.com/v1
MODEL_NAME=gpt-4.1-mini
MODEL_PROTOCOL=chat-completions
MODEL_API_KEY=your-api-key
```

- 默认 `data/` 保存本地业务数据，启用认证后还包含各租户目录；SQL 激活后必须同时备份数据库，不提交这些数据到 Git。
- 认证密钥 `auth.key` 始终本地保存，按 `0600` 创建 / 收紧；Windows 需手工设置 ACL，仅靠 mode 位不足以证明访问权限正确。备份完整目录及独立密钥，避免丢失后无法解密认证配置。
- SQLconnect 密码以明文保存在 `data/sqlconnect.json`，不属于模型 API Key 的加密范围；保护数据目录、Windows ACL 和备份。
- 模型地址不允许指向本机、内网或云元数据地址。
- 业务 API 修改请求需要当前租户上下文的 `X-Platform-CSRF`，启用认证后还需要会话和 `X-CSRF-Token`；登录不解除既有来源和私网 HTTP 限制。
- 同一数据目录只允许一个服务实例；SQL 不提供跨主机运行时安全。当前认证与 Turnstile 不构成公网生产部署保证，不要直接暴露公网。
- 平台登录必须由用户在隔离浏览器中完成；登录、密码与验证码由作者本人处理。应用可在明确授权后代填已保存正文、保存/覆盖草稿及提交审核，不能绕过平台审核、风控或额外声明。
- `PLATFORM_SECRETS_KEY`、模型 API Key、Cookie、localStorage 会话和 token 均属于秘密；不要放入项目正文、截图、日志、工单或 Git。备份本机数据时同时保护加密凭据与独立保存的密钥，不通过前端或聊天发送凭据。
