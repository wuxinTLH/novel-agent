# 番茄平台接入说明

语言 / Language：[中文](番茄平台接入.md) · [English](en/fanqie-integration.md) · [English documentation index](en/README.md)

本说明对应 v0.0.4a 当前源码实现。完整逐步操作见[使用手册](使用手册.md)，项目启动见[README](../README.md)。

## 能力与边界

| 功能 | 当前行为 |
| --- | --- |
| 登录 | 后端启动隔离 Chromium，作者人工登录；核验自动打开作者首页，通过实时用户接口识别稳定账号 |
| 账号与作品 | 读取已核验账号及作品，必须显式绑定目标作品 |
| 分卷 | 只读获取；唯一卷自动选中，多卷必须指定，新建章节不猜测目标 |
| 草稿上传（save_draft） | 本地正式章节按顺序保存草稿并全文回读；完整预览标明新建、复用或同 ID 覆盖，不提交审核 |
| 同章覆盖 | 只允许已核实可编辑草稿；账号、作品、章号、远端状态和指纹不匹配时停止 |
| 提交审核（submit_review） | 显式选择 AI 使用声明，通过单独批准的确认流程送审，并验证准确章节回执；不意味着审核通过或已发布 |
| 正式发布（publishChapter） | 能力始终为 false；不提供直接正式发布或保证审核通过 |
| 浏览器扩展 | [MV3 配对客户端](平台扩展.md)可运行于单用户本机模式，仅双确认配对、检查能力、断开；账号核验、作品读取、草稿保存与送审均不可用 |
| 自动审批 | 项目级浏览器开关，免除本工具的人工批准；服务端保留预览哈希和审批来源 |
| 自动工作流 | 配置目标后，完整真实工作流成功生成、审校并保存章节，自动接续上传或送审 |
| 未知结果 | 只读核对已记录的准确远端 ID，或从官方该章编辑链接人工提供准确章节 ID；必须匹配历史快照，不能证明则保持未知，不盲目重发 |

不提供绕过平台审核、验证码、风控、额外声明或不明确认弹窗的能力；不承诺会话永不过期，也不提供无人值守定时发布服务。

## 安装与会话

```powershell
npm ci
npm run browser:install
npm run dev
```

首次登录需要操作后端所在机器弹出的桌面浏览器。局域网打开应用不等于远程桌面控制登录窗口。

在本机环境配置固定 `PLATFORM_SECRETS_KEY` 后，平台会话才能加密保存并跨后端重启使用。不配置时仅在内存中使用，重启后重新登录。不要把真实密钥、Cookie 或会话内容放进文档、源码和问题截图。

当前账号点击“继续登录 / 重新核验”时，若原连接的 Chromium 窗口仍由当前后端持有，将复用同一个浏览器上下文，不另开窗口；同一待核验登录重复请求也复用原窗口。请先选择准确账号；新建账号入口仍创建独立窗口，不按“唯一窗口”猜测身份。服务重启后不能接管遗留进程或个人浏览器。

人工登录窗口不再在 15 分钟后自动关闭；请完成登录后点击“核验账号”。核验成功后同一个可见 Chromium 窗口继续驻留，每五分钟只读打开作者首页，重新核验稳定作者身份，并加密保存网站实际更新的 Cookie / localStorage（包含网站自行维护的登录凭据），不向前端返回 token。每轮结束后再计时五分钟，忙碌的项目、账号或工作流跳过本轮，避免打断上传/送审；不是精确时钟或永不过期保证。

身份核验、读取及成功写入后也同步网站实际更新的 Cookie / localStorage；没有猜测的“双 token 刷新接口”。身份变化、授权失效或验证码将停止自动刷新并要求重新人工登录，不把其他账号的状态写入原连接。网络暂时失败保留旧凭据，后续周期重试只读核验。手动关闭窗口不会自动重开；断开连接、删除项目或停止服务会清理刷新任务，服务重启不会自动弹窗。更换加密密钥不会解密旧会话，务必保管原密钥。

**未核验的人工登录仍持有平台级排他锁**（账号身份未知），请勿长期搁置：其他租户或账号的平台任务需等你完成核验或关闭窗口。关闭窗口后由监测任务释放登录锁；在途核验结束前不会提前释放。已核验的驻留窗口只在只读刷新或业务操作期间获取账号锁，不长期占用发布锁。不要在驻留窗口手动切换账号或编辑正在由工具操作的章节。

## 操作顺序

1. 在“平台作品”概览点击番茄进入二级页面，按“核验账号 → 绑定作品 → 选择章节 → 预览并批准 → 核对结果”操作。前置条件不足时不能进入写入步骤；结果与异常可随时查看。
2. 在“核验账号”启动番茄人工登录；完成登录后点击核验，程序自动进入作者后台首页读取身份。
3. 在“绑定作品”核对作者，读取作品并绑定准确远端作品；在“选择章节”读取分卷并确认账号、作品、卷 ID。
4. 在“预览并批准”选择章节和动作，每批最多 50 章，按章号处理；送审还需明确 AI 使用声明。手动模式准备完整预览后逐章批准，自动审批模式须显式开启后由准备请求自动批准，但仍需核对结果。
5. 在“核对结果”查看回读结果和审核回执，而不是把 HTTP 请求成功或网页已打开视为上传成功。可请求暂停，当前在途章完成后停止下一章。

当前分离章号/标题编辑器接受 `第1章 标题` 或 `第 1 章 标题`，数字应与本地章号一致。不会擅自删除正文中的标题段落、改写正文或为了匹配结果降低全文校验。

## 全自动工作流

在工作流设置选择全自动，并在平台队列选择绑定、卷、动作与 AI 声明，保存并启用全自动接续。保存该配置是对后续自动操作的明确授权，与临时上传的自动审批开关分开。

完整工作流运行后按“生成 → 审校 / 硬性校验 → 保存或自动采用 → 远端队列”执行。只接续本次运行实际生成并保存的真实章节；演示、单节点、失败、未采用候选、原稿版本冲突不会上传。不从“当前唯一账号”等条件推断远端目标。重启后不自动重放未确定的接续请求。

## 自动化模式的番茄核验

开启“自动审批”，或启用全自动工作流远端接续后，新准备批次的不可变预览会记录 `autoApprove:true`，由此启用自动核验。仅在启动旧手动预览时选择自动批准，不会改写旧预览或追溯开启自动核验。

- 新建草稿时等待准确作品的稳定编辑链接与已批准作者身份，尽早持久化远端章节 ID，再填写正文和保存；不会按标题猜测 ID。
- 若执行抛错且已经记录准确远端 ID，在原账号锁内最多进行一次只读核对。账号、作品、分卷、历史标题、全文及段落必须匹配；送审还必须有匹配审核回执。核对成功且证据持久化后才继续剩余队列，不再执行失败的写入。
- 无 ID、身份/内容不一致、验证码、未知弹窗或核对失败仍停止。不会自动接受平台额外声明、绕过人工核验、重发正文或清空暂存。
- 手动模式仍由用户触发核对。旧的未知批次不因新功能自动重放；人工只读核对成功后仍暂停，恢复剩余队列需要明确批准。

## 状态与故障排查

页面保持打开时会定期同步本地连接、操作回执及队列记录，切回窗口也会同步；这只读取应用本地状态，不会定时读取远端作品、核对草稿或重发正文。后台同步不会清空未提交的选择、审批或显式错误。远端作品列表需独立等待加载证据；仅作者身份就绪、网络失败或尚未出现列表不能证明作品不存在。

| 状态或现象 | 处理方式 |
| --- | --- |
| 预览 | 尚未启动，可核对全文；超期或本地版本变化需重新准备 |
| 排队 / 执行中 | 不重复启动同一内容，可请求当前章结束后暂停 |
| 草稿已回读核实 | 已验证保存，不代表公开发布 |
| 已提交审核 | 已取得匹配回执，不代表审核通过 |
| 写入前失败 | 检查账号、分卷、版本和正文；先修复问题再准备新的安全操作 |
| 结果未知 | 点击“只读核对远端结果（不重发）”；不要重新建批补发 |
| 远端已有稿但本地未知 | 使用已记录 / 已批准的远端 ID；若缺失，从官方**该章编辑链接**人工提供准确章节 ID（非作品 ID），只读核对账号、作品、分卷、历史标题和完整正文；送审还要匹配审核回执 |
| 没有可核实的远端 ID | 不按标题猜测、不根据空列表推断删除，保持未知，人工检查官方作者页 |
| 登录失效 / 验证码 / 额外提示 | 人工处理或重新登录；自动审批不能绕过 |

用户手动触发核对成功后，有剩余未执行章节的批次保持暂停，不会顺带重发或自动恢复；仅上节显式自动化预览在原执行内成功自动核验并持久化证据后可继续余下队列。服务重启后的在途不确定结果同样先人工只读核对。

### 删除作品被队列阻塞

本地书稿为 0 章不意味着没有远端操作历史。删除正文不会删除发布快照：一次新建草稿可能已经在平台产生副作用，但在取得准确章节 ID 或完成全文回读前失败。此时记录必须保持“结果未知”；不能用空书稿、空远端列表或错误代码推断“没有上传”。

删除作品前会读取**本地**阻塞诊断，列出批次、章号、阶段/错误代码、是否已进入写入流程和是否记录准确远端 ID，不请求平台页面、不重发。诊断只是提示，实际删除仍在服务端重新检查；诊断后启动任务也不能绕过保护。可按以下路径处理：

- **确认未写入的闲置批次**：使用“安全取消”停止整个批次，保留原始预览、批准、请求去重与取消时间。要求所有条目均未开始写入、没有远端 ID 或成功/未知结果，且没有执行或核对在途。取消后不可恢复执行；需要重新准备并批准新预览。
- **正在执行或核对**：先暂停并等在途操作真正结束。请求断连、窗口关闭或暂停请求本身不能证明远端副作用已结束。
- **结果未知、仍需继续平台操作**：进入平台结果页使用准确章节 ID 只读核对；缺少 ID 时从官方该章编辑链接取得，不按标题猜测。核对成功不等于自动继续剩余队列；仍需明确恢复。
- **只想删除本地作品，不再等待核对**：待所有执行、核对和人工登录结束后，可在诊断弹窗显式选择“保留平台记录并删除本地作品”，再次确认删除。该入口删除本地作品及正式书稿，但完整保留平台预览、历史快照、未知结果、批准、请求去重和绑定记录，不删除番茄正文、不清空暂存、不自动重传，也不把 unknown 改成成功。历史快照仍是私有数据，因此这不是彻底擦除全部相关数据。服务端重新检查闲置状态、至少保留一个作品及持久化结果，旧客户端或缺少明确确认的请求不能绕过普通删除保护。同一账号、同一远端作品的未核对归档继续阻止新作品通过换章节 ID 重新上传。
- **人工决定丢弃恢复记录**：原有“备份并清空本地暂存”属于单独的危险操作，需要明确确认重复风险，不能作为安全取消的替代或自动动作。该操作会解除历史去重；不保证远端未保存，不会远端删除或自动重传。备份含历史文稿快照，应视为私有数据。两类平台存储顺序处理，不构成跨存储事务，出现备份/持久化失败时必须检查结果，不能自动重复。

“安全取消”不会解决已发生写入但结果未知的旧批次，也不会把它改为成功。删除已取消的本地项目仍需作者再次明确执行删除；不会因取消完成自动删除作品。普通删除仍会阻止未知批次；“保留平台记录并删除本地作品”是不同的显式本地操作，不要求先取得缺失的远端章节 ID。删除后可通过本租户的只读 `GET /api/platforms/deleted-project-records` 查看保留记录的元数据；该接口不返回正文或凭据，不提供归档批次重新执行入口。此版本保留证据与写入阻止，不宣称提供已删除作品的完整图形化核对/恢复工作台。

“移出本地暂存列表”仅在当前浏览器隐藏非活动记录，服务端审计、幂等与未知结果阻塞继续有效，可恢复显示。独立的“备份并清空本地暂存”会清空当前作品的本地平台预览、操作、回执及全部批次（含隐藏记录），解除历史去重阻塞，未来上传有重复章节风险；必须先核对官方后台并明确确认。两者都不删除番茄远端正文或本地正式章节，清空也不删除登录绑定、不自动重发。

编辑器回读按真实段落结构序列化，避免 CSS 造成 `innerText` 额外空行；保留有意空段、换行与正文标题。该修复有本地 Chromium 回归覆盖，但不应据此宣称每个线上未知结果都由同一个原因造成。

批次 API 基路径为 `/api/projects/:projectId/platform-publication-batches`，包含 `GET /`、`GET /volumes`、`POST /prepare`、`POST /:batchId/start`、`POST /:batchId/resume`、`POST /:batchId/pause`、`POST /:batchId/reconcile`、`POST /:batchId/cancel`。取消接口要求 `{ confirmed:true, approvalHash }`，其中哈希必须为原始预览哈希，并再次检查无在途、无远端写入证据。项目级 `GET /api/projects/:projectId/platform-deletion-blockers` 仅返回删除阻塞元数据，不含正文或凭据。`prepare` 可显式携带 `autoApprove:true`；启动要求准确预览哈希和明确授权，不应把旧接口当作绕过审批入口。

测试使用临时目录、本地模拟接口和 Chromium，不调用真实账号写入。用户曾确认真实账号身份 / 作品读取及草稿上传成功；本轮自动送审和全自动接续仍需作者针对真实目标验收，不把离线测试描述成平台审核通过。
