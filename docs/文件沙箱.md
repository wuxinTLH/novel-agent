# 文件准入、内容重构与安全边界

语言 / Language：[中文](文件沙箱.md) · [English](en/file-sandbox.md) · [English documentation index](en/README.md)

这里的“文件沙箱”指文件准入检查、受限解析和内容重构。上传原件不能直接成为浏览器预览或模型图片输入；通过检查后只使用重构结果。解析失败、超时、格式不符或容量超限时拒绝，不回退到原始文件。

这不是完整的操作系统沙箱，也没有证明能够抵御所有恶意文件。图片解码器包含原生代码，子进程与服务端使用同一操作系统用户；当前实现没有独立权限令牌、网络隔离或进程 RSS 硬上限。不能把“通过检查”解释为杀毒证明或 100% 安全。

## 输入和消费入口

| 入口 | 准入与输出 |
| --- | --- |
| 作品资料批量上传 | TXT、Markdown、JSON 做严格文本解码；JSON 重新序列化；PNG、JPEG、WebP 解码后重编码为 PNG。整批检查成功后才发布。 |
| 作品封面 | 图片解码并重编码为 PNG，持久化重构副本。 |
| 本地头像 | 浏览器先请求头像检查接口，只解码服务器返回的 PNG；随后裁剪为本地头像。原始上传文件不会先交浏览器图片解码器。 |
| 手动章节 TXT | 浏览器上传到正文检查接口，严格按 UTF-8 或 GB18030 解码，再把检查结果放入编辑器。 |
| 临时文档阅读 | DOCX 验证完整 ZIP 后在子进程转换为语义 HTML，移除图片、链接、样式、嵌入对象及活动内容。原始 OOXML 不发布。PDF 暂时拒绝。 |
| 存量 uploads 图片读取 | 只接受 UUID 文件名和 PNG/JPG/JPEG/WebP 后缀；有界读取后再次重构为 PNG。旧文件也必须经过检查，不直接静态返回。原文件不被覆盖。 |
| 模型图片出站 | 图片资料经同一安全读取函数重新解码后，以 PNG 传给模型；不能仅凭数据库 MIME 或旧文件后缀信任原始字节。 |

输入限制在服务器执行；前端格式和大小提示不能替代服务器检查。身份、租户和 CSRF 校验由外层服务执行，安全读取路由仍处于租户边界内。手动粘贴正文属于文本业务输入，不会作为可执行 HTML 渲染。

实现入口：[准入与重构](../packages/server/src/features/file-sandbox/sandbox.ts)、[multipart 准入](../packages/server/src/features/file-sandbox/upload.ts)、[租约](../packages/server/src/features/file-sandbox/upload-lease.ts)、[存量安全读取](../packages/server/src/features/file-sandbox/safe-read.ts)、[文档解析](../packages/server/src/features/documents/parser.ts)。

## 独立 Web 交付不改变上传边界

后端设置 `SERVE_WEB=false` 只关闭 Web 静态托管与 SPA，不关闭受保护的 `/uploads` 读取和文件业务 API。独立静态服务器应同源反代 `/api` 与 `/uploads` 到同一个后端，不直接挂载数据目录 / uploads 原件，也不将文件错误替换为 SPA HTML；Cookie、来源、租户和 CSRF 校验保持不变。`WEB_DIST_DIR` 只能指向可信前端构建产物，不能用来公开业务数据。部署方式见[使用手册](使用手册.md#前后端独立构建与同源部署)。这不是新 OS 隔离能力。

## 拒绝策略与限制

容量单位 MiB = 1024 × 1024 字节。

| 项目 | 限制 |
| --- | --- |
| 文本资料、手动 TXT | 每文件 2 MiB；禁止空文件、无效编码和二进制控制字符。 |
| 图片资料、封面上传 | 每文件 4 MiB。 |
| 头像、DOCX 上传 | 每文件 8 MiB。 |
| 批量资料 | 每批最多 10 个文件；multipart 字段、字段字节数和总 part 数同样受限。 |
| 存量图片读取、图片重构输出 | 最大 16 MiB；内部存量读取限值不扩大外部上传限值。 |
| 图片尺寸 | 最大 24000000 像素，宽高分别不超过 6000；拒绝多页图片。 |
| 图片解码 | 独立子进程；关闭 sharp 缓存；sharp 并发 1；V8 old-space 96 MiB；10 秒截止。 |
| DOCX ZIP | 压缩输入最大 8 MiB，最多 512 条目，总展开内容最大 32 MiB，单项展开比不超过 200；验证截止 5 秒。 |
| DOCX 转换 | 子进程 V8 old-space 128 MiB；10 秒截止；HTML 输出最大 4 MiB。 |
| 临时文档留存 | 每作品最多 10 份、每服务最多 64 份；留存内容总量最大 64 MiB；30 分钟过期。 |

图片签名必须与扩展名一致；最终必须完整解码成功。JPEG/PNG 后附载荷和原始元数据不随重构图片发布。SVG、可执行文件和伪装图片不放行。DOCX 会拒绝不安全路径、重复条目、加密、符号链接、异常压缩、宏、外部关系、XML 实体和嵌入活动内容；随后仍进行 HTML 标签白名单清理。PDF 没有可靠内容重构实现，因此即使文件签名正确也拒绝。

存量读取拒绝目录、符号链接、越界路径和检查到的文件替换；每次重新净化，没有持久“曾扫描通过”状态，也没有可能过期的净化结果缓存。读取不会覆盖用户原文件，因此原目录仍须按敏感数据保护。这个机制不保证抵御具有本机文件写权限的攻击者。

## 并发、取消和失败

每个运行时进程最多两个文件处理租约，图片读取与上传共享该限制。多租户工作进程分别计数，并非整台服务只有两个；部署容量应按工作进程数量计算。

租约在 multipart 缓冲前取得。解析中连接断开会停止输入、取消租约并禁止迟到回调启动扫描。解析成功后租约交给处理函数：响应连接断开只触发取消，正在运行的解码子进程被终止，必须等到子进程关闭、处理函数 finally 清理后才返还并发名额。客户端不能通过反复断开响应提前释放名额，堆积仍在运行的解码器。校验错误和无文件等提前返回路径同样必须在 finally 释放。

解码子进程只接收最小环境变量白名单，清空 NODE_OPTIONS，工作目录设为解析依赖目录，避免默认继承服务端密钥环境和数据工作目录。解析器不可用时拒绝文件；业务处理不得捕获后改用原始字节。

## 仍然存在的边界

V8 old-space 限值不等于进程内存总量限制：Buffer、原生解码库和系统分配可在 V8 堆之外使用内存。像素限制、并发名额和截止时间降低风险，不能替代操作系统内存、CPU 和进程数限制。DOCX ZIP 验证的一部分仍在服务进程中执行，具有有界展开量和条目数，但并非所有不可信输入处理都已移出主进程。

现有测试覆盖格式伪装、重构去载荷、尺寸限制、危险 DOCX、存量读取和断连并发租约。测试没有证明底层 sharp/libvips、压缩库或文档解析库不存在原生漏洞，也没有实现病毒签名扫描、所有格式漏洞检测或网络出站防火墙。

Node 22 的权限模型可以作为附加防误用层：22.13.0 起使用 `--permission`，更早的 Node 22 使用 `--experimental-permission`。纯 JavaScript 文档解析可只开放依赖目录读取，禁止写文件、启动子进程、worker 和调试器。sharp 需要允许原生插件；原生代码及 Node 22 不受该模型限制的能力不能因此被视为隔离。Node 官方明确该模型不为恶意代码提供安全保证，参见 [Node 22 权限说明](https://nodejs.org/docs/latest-v22.x/api/permissions.html)。当前实现没有启用这些标志，不应把建议描述为已经完成。

## 面向不可信用户的部署

对公网或敌对文件，应把解析服务放进真正的操作系统隔离环境，单独运行身份，无法读取作品库、数据库凭据、浏览器会话和服务密钥；只通过有界 IPC 输入文件并返回重构结果。

Windows 可使用 AppContainer 或受限令牌，结合 Job Object 设置总内存、CPU、进程数量及关闭时终止整组进程，明确禁用网络能力。Linux 可采用隔离 UID、只读最小依赖文件系统、无网络命名空间、seccomp 及 cgroup 的内存/CPU/进程数限制。容器应按这些权限与配额配置，不能仅因采用容器名称就视为完成隔离。更新解析依赖、锁定版本并持续测试失败路径仍有必要。
