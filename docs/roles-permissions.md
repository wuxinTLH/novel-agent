# 角色与权限

## 四种角色与权重

| 角色 ID      | 名称       | 权重 |
| ------------ | ---------- | ---: |
| `superadmin` | 超级管理员 | 1000 |
| `operations` | 运维管理员 |  100 |
| `admin`      | 管理员     |   99 |
| `writer`     | 作家       |   10 |

权重只是排序元数据，**不是权限继承规则**。运维管理员的 100 高于管理员的 99，不代表运维可以管理用户、配置存储、初始化 SQL、取消维护任务或生成恢复计划。授权以共享权限表中的显式角色名单为准；新增功能必须声明权限，不能通过比较权重或“不是作家”来判断权限。

## 显式授权矩阵

“✓”表示授权，“—”表示拒绝。

| 权限                                                                    | 超级管理员 | 管理员 | 运维管理员 | 作家 |
| ----------------------------------------------------------------------- | :--------: | :----: | :--------: | :--: |
| `workspace.use`                                                         |     ✓      |   ✓    |     ✓      |  ✓   |
| `admin.access`、`admin.status.read`                                     |     ✓      |   ✓    |     ✓      |  —   |
| `users.read`、`users.manage`                                            |     ✓      |   ✓    |     —      |  —   |
| `roles.manage`                                                          |     ✓      |   —    |     —      |  —   |
| `storage.read`                                                          |     ✓      |   ✓    |     ✓      |  —   |
| `storage.manage`、`sql.initialize`                                      |     ✓      |   ✓    |     —      |  —   |
| `maintenance.read`、`maintenance.backup`、`maintenance.validate`        |     ✓      |   ✓    |     ✓      |  —   |
| `maintenance.restorePlan`、`maintenance.cancel`、`maintenance.commands` |     ✓      |   ✓    |     —      |  —   |
| `security.read`                                                         |     ✓      |   ✓    |     —      |  —   |
| `security.manage`                                                       |     ✓      |   —    |     —      |  —   |

用户管理还受目标角色约束：超级管理员可管理已知角色；管理员只能管理作家及运维管理员，不能管理同级管理员或超级管理员，也不能分配角色。运维管理员和作家不能管理用户。未知操作者、未知目标或未知权限一律拒绝；不回退为管理员。

## 兼容与迁移

- 旧角色 `user` 规范化为 `writer`，获得且仅获得作家权限；既有账号不应因此升级为管理员。
- 认证继续默认 **OFF**，沿用现有认证开关及 CLI 启用流程；四角色迁移不自动启用认证，也不引入新的环境开关。
- 认证关闭时保留原有本机管理员使用方式，但不是取消原有本机访问、管理员凭证或 CSRF 边界。
- 在线维护组件的可选 `role` 属性仅在未传入（`undefined`）时兼容本机/旧模式，以超级管理员能力展示。认证模式下父组件必须传入实际已认证角色，不能以省略角色作为鉴权回退；其它未知值应拒绝。
- 前端隐藏无权限的步骤与按钮，并在提交函数中再次校验；最终授权始终由服务端逐次执行，隐藏按钮不构成安全边界。

## 在线与离线维护边界

- 运维管理员可以读取维护状态、创建全应用备份及校验备份完整性；不能取消任务、生成离线恢复计划或使用仅管理员开放的维护命令。
- 在线备份覆盖全部租户、控制面和配置的业务数据库，不是当前用户的数据导出。备份含敏感资料，创建时需要显式确认，且全部租户会短暂停顿；没有可靠全局静默屏障时必须改用停服 CLI。
- 页面不提供备份浏览器下载、任意文件路径访问或在线恢复。完整性校验不是业务语义、密钥可解密或可成功启动的保证。
- 管理员生成的恢复计划只是操作指引，**不执行恢复**。实际恢复和迁移必须安排停服窗口，由有主机权限的管理员使用离线 CLI，独立保管外部密钥并检查空目标、数据库映射及恢复日志。
- Web 角色和权重不授予操作系统、数据库或离线 CLI 权限。离线操作仍受主机权限、凭证及恢复工具自身的安全校验约束。

## 回归测试

共享权限测试使用现有 `node:test` 与 `node:assert/strict`，覆盖四角色精确权重、完整授权矩阵、旧角色映射、未知输入拒绝及用户管理目标约束。可单独执行：

```sh
node node_modules/tsx/dist/cli.mjs --test shared/permissions.test.ts
```

仓库统一测试入口为 `node scripts/test.mjs`；共享目录必须包含在该入口的 `.test.ts` 发现范围中。
